Inspect executable YAML & OpenCypher definitions

Drop directly into .codeexplorer/gates/ or adapt paths with your AI agent
SIG-CA-B-001 Domain Core Purity (OpenCypher YAML) 
id: SIG-CA-B-001
category: Architectural
platform: agnostic
scope: Module
dimension: Boundaries
severity: Error
name: Domain Core Purity
description: Domain types and functions must never call or depend on Application, Infrastructure, or Presentation layers.
query: >-
  MATCH (src:Function)-[:CALLS]->(dst:Function)
  WHERE (src.file_path CONTAINS '/Domain/' OR src.file_path CONTAINS '/Core/')
    AND (dst.file_path CONTAINS '/Infrastructure/' OR dst.file_path CONTAINS '/Application/' OR dst.file_path CONTAINS '/Api/' OR dst.file_path CONTAINS '/Web/')
  RETURN src.file_path AS file, src.start_line AS line, src.name AS symbol, dst.name AS target,
         'Domain symbol ' + src.name + ' calls outer-layer symbol ' + dst.name AS message
SIG-CA-B-002 Application Layer Isolation (OpenCypher YAML) 
id: SIG-CA-B-002
category: Architectural
platform: agnostic
scope: Module
dimension: Boundaries
severity: Error
name: Application Layer Isolation
description: Application use cases define ports and orchestrate Domain logic without importing concrete Infrastructure or Delivery adapters.
query: >-
  MATCH (src:Function)-[:CALLS]->(dst:Function)
  WHERE (src.file_path CONTAINS '/Application/' OR src.file_path CONTAINS '/UseCases/')
    AND (dst.file_path CONTAINS '/Infrastructure/' OR dst.file_path CONTAINS '/Persistence/' OR dst.file_path CONTAINS '/Api/')
  RETURN src.file_path AS file, src.start_line AS line, src.name AS symbol, dst.name AS target,
         'Application use case ' + src.name + ' depends directly on adapter ' + dst.name AS message
SIG-CA-B-003 No Delivery-to-Database Bypass (OpenCypher YAML) 
id: SIG-CA-B-003
category: Architectural
platform: agnostic
scope: Method
dimension: Boundaries
severity: Error
name: No Delivery-to-Database Bypass
description: HTTP controllers, GraphQL resolvers, and CLI handlers must dispatch through Application use cases rather than issuing SQL or ORM queries directly.
query: >-
  MATCH (q:Query)-[:ACCESSED_BY]->(fn:Function)
  WHERE fn.file_path CONTAINS '/Controllers/' OR fn.file_path CONTAINS '/Api/' OR fn.file_path CONTAINS '/Resolvers/'
  RETURN fn.file_path AS file, fn.start_line AS line, fn.name AS symbol, q.name AS target,
         'Delivery handler ' + fn.name + ' executes database query directly, bypassing Application layer' AS message

2. Complete architecture encyclopedia catalog.

Compare architectural styles by structural trade-offs and the graph-level invariants that keep AI agents from eroding them over time.

6 Canonical Architecture Packs (26 Semantic Invariant Gates) Agnostic + .NET, TS, Go, Python, Java, Rust
Architecture Style Core Structural Principle What Graph SIG Catches Beyond Import Linters Gates Action
Clean Architecture
clean-architecture		 Concentric onion rings where Domain and Application own interfaces and Infrastructure implements adapters. Catches Controllers issuing SQL/ORM queries and Domain methods calling outward concrete implementations. 5 gates
Hexagonal
hexagonal		 Strict separation between Application Core, Driving (inbound) adapters, and Driven (outbound) adapters. Prevents inbound HTTP/gRPC adapters from calling outbound DB/queue adapters directly without a Port interface. 4 gates
Modular Monolith
modular-monolith		 Autonomous vertical business modules inside a single deployment unit communicating only via public facades. Blocks cross-module internal class calls and cross-module SQL writes/joins into another module’s owned tables. 5 gates
Vertical Slice
vertical-slice		 Each feature slice encapsulates its own request, handler, validation, and data access with zero sibling coupling. Detects hidden lateral calls between sibling feature slices (Features/Orders calling Features/Billing). 4 gates
Feature-Sliced Design
feature-sliced-design		 Unidirectional frontend hierarchy: app to pages to widgets to features to entities to shared. Enforces strict downward imports, public index.ts slice APIs, and zero cross-feature upward leaks. 4 gates
Microservices DB Isolation
microservices-isolation		 Database-per-service ownership where cross-service state changes flow strictly over APIs or async topics. Traces L4 SQL/ORM Table lineage across services to block shared-database coupling and synchronous fan-out chains. 4 gates

3. Adopt any pack on a legacy codebase in 30 seconds.

You do not need a greenfield repository to enforce strict architecture. SHA-256 baseline ratcheting freezes existing technical debt so CI passes immediately while blocking every new violation.

Step 01

Install or download pack

Drop the selected .yaml gate pack into .codeexplorer/gates/ or ask your MCP coding agent to map its layer paths onto your actual workspace folders.

ce gate install modular-monolith
Step 02

Freeze legacy baseline

Run ratchet initialization once. Existing violations are hashed by symbol identity rather than line numbers, so unrelated edits never cause false alarms.

ce gate ratchet --update
Step 03

Enforce on every edit

Pre-commit hooks, CI pipelines, and AI agents via check_semantic_gates verify all rules in milliseconds with zero LLM tokens.

ce gate check (Exit 0 / Exit 1)
