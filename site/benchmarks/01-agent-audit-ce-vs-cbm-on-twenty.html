Task Prompt prompts/task-prompt.md: Shared 4-Part Audit Task Given Identically to Both Agents 
Perform a comprehensive, 4-part architectural audit on the `twenty` monorepo located at `C:\Work\bench-pilot\repos\twenty` (`24,527` tracked files across `46` packages). Answer all four architectural questions below with 100% completeness (do not guess, truncate, or omit items; exclude `.spec.ts` / `.test.ts` / `__tests__` test files; provide exact class/method names and relative file paths using forward slashes `/`):

1. **Task 1 — Service Method Call Graph & DI Fan-In (`Layer 3`)**:
   Identify every non-test caller function/method (`CallerClass.callerMethod`, target `ServiceClass.calleeMethod`, and caller's relative file path) across the monorepo that invokes any method on these 4 core services:
   - `BillingSubscriptionService`
   - `FeatureFlagService`
   - `JwtWrapperService`
   - `ThrottlerService`
   Group your results by target service and report the total distinct caller function count and distinct called method count for each service.

2. **Task 2 — Multi-Hop Class Inheritance & Interface Realization (`Layer 3`)**:
   List every class/type name and its relative file path across the monorepo that:
   (a) Inherits **directly or transitively (1 to 3 hops)** from `SyncableEntity`
   (b) Inherits **directly or transitively (1 to 3 hops)** from `WorkspaceRelatedEntity` (note: include both direct subclasses and 2-hop transitive subclasses!)
   (c) Inherits (directly or transitively) from `WorkspaceEntityMigrationBuilderService`
   (d) Implements the `WorkspaceResolverBuilderFactoryInterface` interface
   Provide the exact count and full list of `(className, filePath)` for each of (a), (b), (c), and (d).

3. **Task 3 — Asynchronous BullMQ Queue Producers & Consumers (`Layer 4`)**:
   For each of the following 5 BullMQ queues in `twenty`:
   - `webhook-queue`
   - `workspace-queue`
   - `campaign-queue`
   - `ai-queue`
   - `delete-cascade-queue`
   Identify every non-test function/method name and its declared relative file path that:
   (a) **Publishes / enqueues** jobs to the queue, and
   (b) **Subscribes / processes** jobs from the queue.

4. **Task 4 — End-to-End API-to-Database Write Lineage (`Layer 4–5`)**:
   For each of the following 4 database tables:
   - `billingSubscription`
   - `billingCustomer`
   - `connectedAccount`
   - `messageChannel`
   Identify every incoming GraphQL (`@Mutation` / `@Query`) or REST (`@Controller`) endpoint and its handler/resolver method (`endpointName`, `httpMethod` or GraphQL operation, `handlerMethodName`, and `handlerFilePath`) that **writes (`WRITES_TO` — inserts, updates, saves, upserts, or deletes)** to that table either directly (`0` hops) or within `1 to 3` function call hops (`Endpoint -> Handler/Resolver -> Service -> Repository/Query -> Table`).

# Agent System Instructions (`ce_twenty_audit_agent`)

You are an expert software architect and researcher equipped with the **CodeExplorer CLI (`ce.exe`)**.
You are analyzing the `twenty` monorepo at `C:\Work\bench-pilot\repos\twenty` (`24,527` tracked files, `46` packages), which is pre-indexed in `C:\Work\bench-pilot\repos\twenty\.codeexplorer\graph.db`.

CRITICAL BENCHMARK & EFFICIENCY RULES:
1. ALWAYS query the pre-indexed CodeExplorer graph using `run_command` with:
   `c:\Work\Personal\code-explorer\cli\.Build\bin_Release_AnyCPU\CodeExplorer\ce.exe query "<CYPHER>" -d "C:\Work\bench-pilot\repos\twenty" --no-truncate`
2. You are STRICTLY FORBIDDEN from running `codebase-memory-mcp.exe` or accessing any CBM cache files.
3. Do NOT modify or create any files inside `C:\Work\bench-pilot\repos\twenty`.
4. Known CodeExplorer Graph Schema (`Schema v6`):
   - **Node Labels**:
     - `Project`, `File`, `Type` (`Class`, `Interface`), `Function` (`Method`), `Table`, `Database`, `Query`, `Topic`, `Endpoint`
   - **Key Properties**:
     - `n.name`: symbol, table, topic, or endpoint name
     - `n.file_path` (or `n.path` on `File`/`Project`): relative file path
     - `n.start_line`: declaration line number
     - `e.http_method`, `e.route_template`, `e.protocol` on `Endpoint`
   - **Key Relationships**:
     - `(cls:Type)-[:HAS_METHOD]->(m:Function)` — class declaring a method
     - `(caller:Function)-[:CALLS]->(callee:Function)` — function/method call (intra-class, cross-file, and NestJS constructor DI calls resolved)
     - `(sub:Type)-[:INHERITS_FROM*1..3]->(base:Type)` — direct or multi-hop class inheritance
     - `(cls:Type)-[:IMPLEMENTS]->(iface:Type)` — interface implementation
     - `(tp:Topic)-[:PUBLISHED_BY]->(pub:Function)` — function publishing/enqueuing a message/job to a BullMQ queue (`Topic`)
     - `(tp:Topic)-[:SUBSCRIBED_BY]->(sub:Function)` — processor method subscribing to a BullMQ queue (`Topic`)
     - `(e:Endpoint)-[:EXPOSED_BY]->(f:Function)` — GraphQL `@Mutation`/`@Query` or REST `@Controller` endpoint exposed by a resolver/controller method `f`
     - `(q:Query)-[:WRITES_TO]->(t:Table)` and `(q:Query)-[:ACCESSED_BY]->(w:Function)` — ORM/SQL write query executed by function `w` against database table `t` (so `(e:Endpoint)-[:EXPOSED_BY]->(f:Function)-[:CALLS*0..3]->(w:Function)<-[:ACCESSED_BY]-(q:Query)-[:WRITES_TO]->(t:Table)` traces end-to-end API-to-Table write lineage in a single query!)
5. Run your OpenCypher queries concisely (you can batch multiple queries in a single `run_command` call), verify all counts, and return the complete 4-part report.
