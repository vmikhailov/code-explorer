Why AST indexers stop short of software architecture.

First-generation MCP graph tools parse syntax trees into files, classes, and direct function calls (Layers 1 to 3). Production systems communicate through dependency injection, REST/gRPC/GraphQL routers, message brokers, and ORM database tables (Layers 4 and 5).

Why CodeExplorer finishes 24,527 files in 147 seconds while Graphify stalls past 45 minutes

ce: 51.0 s Single-Pass Topological Layer 3

Orders all 46 packages in twenty via Kahn’s algorithm (twenty-shared and twenty-ui before twenty-server and twenty-front) and runs Tree-sitter C-API parsing, UAST construction, and 250 fused declarative framework visitors in a single pass.

36,644 physical files
ce: 24.0 s Layer 4 & Layer 5 Global Linking

Synthesizes semantic endpoints, queues, and ORM tables in 5 seconds, then resolves 578,143 cross-project symbol references and late-binds 5,092 service calls in 19 seconds using project-scoped hash indices.

17,382 lineage edges
ce: 17.9 s Deferred-Index SQLite Schema v6 Bulk Flush

Streams 456,711 nodes and 960,660 integer-keyed (rowid) edges in a single unindexed SQLite transaction, then builds partial B-Tree indices bottom-up.

784.0 MB graph.db
Graphify: DNF Three Algorithmic Bottlenecks in Graphify v0.9.104

1) detect() takes 117.1s before parsing starts. 2) _JS_CACHE_BYPASS_SUFFIXES in extract.py:10676 bypasses AST caching for all TS/JS files and re-parses all 24,048 files a second time sequentially on one Python thread (resolution.py:2585). 3) _apply_symbol_resolution_facts (resolution.py:1872) runs a quadratic O(|uses| * |nodes|) loop (~60 billion Python iterations across 300k nodes).
