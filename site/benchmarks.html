Part A: Autonomous AI agent audits (1 – 3).

Paired A/B runs where two identical LLM agents (Gemini Flash) receive the exact same architectural audit prompt and work autonomously until they submit their final report.

1 · AGENT AUDIT · PUBLIC MONOREPO Winner: CodeExplorer

twentyhq/twenty (24.5k files): CodeExplorer vs. codebase-memory-mcp

Tested on the open-source twenty monorepo (46 packages, 24,527 files, 2.49M LOC). Both agents started with pre-built graph indexes.

  • Time to answer1m 16s vs. 16m 46s (13.24×)
  • LLM turns / Tool calls7 / 11 vs. 56 / 62
  • Cumulative input tokens268K vs. 4.41M (16.46×)
  • Direct recall from graph100% (454/454) vs. 3.96% (18/454)
  • Final report recall100% vs. 99.56% (452/454)
What happened: CBM returned 0 cross-file NestJS DI calls and 0 matches on Tasks 2–4. At Turn 5, the CBM agent abandoned the graph, wrote 11 Python scripts, and recovered 452/454 items (missing 2 callers in RecordExportWorkspaceService).

2 · AGENT AUDIT · 324 MICROSERVICES Winner: CodeExplorer

324-Service Platform (13.8k files): CodeExplorer vs. ripgrep

Tested on a distributed production platform (450 modules: 324 microservices, 93 shared libraries, 33 workers, 13,782 files across TS, Go, SQL).

  • Time to answer3m 56s vs. 29m 52s (7.59×)
  • LLM turns / File reads23 / 0 vs. 285 / 114
  • Cumulative input tokens393K vs. 17.19M (43.70×)
  • Context compactions0 vs. 1 (at Turn 162)
  • Blast-radius recall100% vs. ~82% (9 services missed)
Transparency note: Both agents tied at 100% on Tasks 1 and 4. On Task 2, ripgrep missed 9 RTB services wired via environment host constants. Because this repo is private, service names are anonymized; use Benchmark #1 for public verification.

Part B: Deterministic indexer & MCP server benchmarks (4 – 5).

Direct head-to-head measurements of cold indexing speed, disk/RAM footprint, ground-truth recall (371 items sampled with fixed seed 42), and single-shot MCP JSON-RPC latency on twenty (2.49M LOC) and immich (461k LOC).

4 · INDEXER & MCP · VS. CBM Recall: ce · twenty Scan: CBM

CodeExplorer vs. codebase-memory-mcp (CBM)

Compares ce and CBM across cold indexing, 130 Layer 1–3 Common Ground items, 241 Layer 4–5 Architecture items, and MCP tool latency.

  • Part 1 Common Ground Recall (L1–L3, 130 GT)ce 78% (102/130) vs. CBM 38% (49/130)
  • Part 2 Architecture Recall (L4–L5, 241 GT)ce 97.5% (235/241) vs. not modeled
  • Cold index on immich (3.2k files)ce 17.6s (55 MB) vs. CBM 20.6s (282 MB)
  • Cold index on twenty (24.5k files)CBM 96.9s (2.08 GB RAM) vs. ce 147.3s (4.66 GB RAM)
  • OpenCypher query latency (warm)ce 3.1–4.7 ms vs. CBM 38.1–71.2 ms
Where CBM won: CBM indexed twenty 1.52× faster with 2.2× lower peak RAM (because it extracts only L1–L3 syntax/call graphs), and was faster on single-symbol lookup (AuthService). CBM also provides compare_graphs, ingest_traces, and manage_adr.

5 · INDEXER & MCP · VS. GRAPHIFY Winner: CodeExplorer · Call Graph Tie on immich

CodeExplorer vs. Graphify

Compares ce against graphifyy (Python/NetworkX AST & knowledge-graph tool) on the same twenty and immich repositories and 371 ground-truth items.

  • Cold index on immich (3.2k files)ce 17.6s vs. Graphify 107.6s (6.1× faster)
  • Cold index on twenty (24.5k files)ce 147.3s vs. Graphify DNF (>45m timeout)
  • Part 1 Common Ground Recall (L1–L3, 130 GT)ce 78% vs. Graphify 18% (immich: 73% vs. 35%)
  • Part 2 Architecture Recall (L4–L5, 241 GT)ce 97.5% (235/241) vs. not modeled
  • MCP server cold init on immichce 599 ms (64 MB) vs. Graphify 3,683 ms (163 MB)
Where Graphify tied / differs: On immich, Graphify tied ce at 100% (20/20) on Call Graph & DI (C6) and 15% (3/20) on Inheritance (C7). Evaluated in deterministic --code-only mode; Graphify also offers Leiden clustering, Obsidian exports, and optional LLM document synthesis.
